# 攻略知识库维护

## 触发条件

- 新增英雄、卡牌、流派，或游戏版本改动影响构筑。
- 推荐理由、核心卡、开局路线需要修正。
- 网页编辑器的保存/检索/热更新出问题。

## 事实来源

- `data/guides/*.md`：每篇一个英雄，包含主/副流派、抓牌顺序、克制关系和候选卡池。
- `data/kb/`：由 `tools/build_guides.py` 生成的检索索引；不要手工改生成物。
- `tools/verify_guides.py`：检查缺失英雄、空章节、坏链接和字段。
- 数值和机制以 `docs/规则与数据核对.md`、`docs/社区来源与版本差异.md` 的记录为准。

## 工作流

1. 先跑 `python tools/verify_guides.py`，确认基线通过；失败时先修数据，不要先改代码。
2. 编辑 `data/guides/<英雄>.md`，保留现有章节结构：定位、推荐流派、核心卡、开局、克制。
3. 重新生成索引：
   ```powershell
   python tools/build_guides.py
   ```
4. 打开 `http://127.0.0.1:8777/library`，抽查该英雄的图鉴与推荐理由。
5. 再跑 `python tools/verify_guides.py` 与相关 `tests/test_kb.py`。

## 验收清单

- [ ] 60 个英雄都有攻略文件，文件名为英雄名。
- [ ] 每篇至少有主流派、核心卡和开局路线，不出现空标题。
- [ ] 推荐理由引用的是当前开放流派，不把禁用流派写成主路线。
- [ ] 网页保存后无需重启即可生效；刷新页面能看到改动。
- [ ] 不把个人对局结果当作官方胜率写进知识库。

## 热更新边界

攻略是 Markdown 热加载；卡牌/英雄结构化数据仍要走 `data-rebuild` 的导入流程。不要把
结构化 JSON 当 Markdown 手改，否则下一次重建会覆盖。
