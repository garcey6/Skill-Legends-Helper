# 架构与实现

本文面向需要改代码或排查底层问题的人。日常使用见 [USER_GUIDE](USER_GUIDE.md)。

## 进程与线程

浮窗模式是一个 Python 进程，包含：

- **Tk 主线程**：窗口主循环、热键轮询、截图、识别、渲染。
- **热键线程**：`RegisterHotKey` 的消息循环，把识别/隐藏/退出事件投递到队列。
- **HTTP 线程**：本地网页控制台，与浮窗共用同一个进程、同一份攻略库。

网页版模式只启动 HTTP 线程和识别/推荐引擎，不创建浮窗。

识别期间主线程会短暂阻塞（约 0.9 秒）；浮窗先显示「正在识别」，不会卡死游戏。

## 为什么用 Tkinter + Pillow

- 不需要 Electron、WebView2 或浏览器窗口，启动快、占用低。
- 浮窗可以用 Win32 扩展样式做置顶、不进任务栏、不抢焦点。
- 整张卡片由 Pillow 绘制，排版和网页版视觉一致，改版不用改 Tk 布局。
- 只依赖 Python 标准库和已有的 `numpy / Pillow`。

## 截图流程

1. 查找游戏窗口：优先标题包含「选技大乱斗 / Skill Legends / 选技」的最大客户区窗口，否则使用前台窗口。
2. 排除助手自己的浮窗和控制台，避免截到自己。
3. 隐藏浮窗约 0.2 秒。
4. 截取游戏客户区，按虚拟桌面坐标裁剪。
5. 捕获方式：
   - `BitBlt` + `CAPTUREBLT` 抓屏幕；
   - 如果全黑，尝试 `PrintWindow(PW_RENDERFULLCONTENT)`；
   - 仍然黑屏则显示错误卡，提示改用无边框窗口。
6. 最近一次截图默认写入 `data/captures/last.png`；`--no-save-capture` 可关闭。

启动时设置 **Per-Monitor DPI Aware V2**，保证 125% / 150% 缩放下截图和浮窗坐标一致。

## 流派识别

13 个流派的图标有大量同色系（闪避 / 急速 / 冰冻都是蓝书），OCR 又受字体影响，所以采用模板匹配：

1. 找到 5 个红色禁用环（60×60、亮红色），它们固定在最后 5 个格子。
2. 用这 5 个环反推 4 列 × 4 行的网格和行距，得到 13 个格子的中心。
3. 每个格子右侧裁出流派名，取白色文字连通域，归一化成 3 个字格；比较前两个字（第三个都是「流」）。
4. 与 13 张文字模板做归一化互相关，一对一贪心匹配。
5. 前 8 格为启用，后 5 格为禁用。

在 1800px、1280px、900px 宽度和 JPEG 70% 压缩下测试通过。

## 英雄识别

从顶部 5 个石质名牌中检测前 3 个，按名牌宽度固定比例裁出头像，与模板做归一化互相关。

- 仓库内置 3 个头像模板：森林游侠、神秘法师、魔镜。
- 识别特征缩放到 96×128 灰度图。
- 60 个英雄的**展示立绘**是 300×300，放在 `data/art/`，只用于显示，不参与识别。
- 识别是闭集：没学过的英雄不会猜，置信度低于阈值会留空并提示。
- 第一次遇到新英雄时，在网页上传截图并手动选择英雄，程序会保存头像模板；下一次识别自动加载。

因此自动识别覆盖率取决于 `data/templates/heroes/` 中的模板数量，而不是 `data/art/` 的 60 张立绘。

## 浮窗渲染

- 卡片尺寸 620×560，按屏幕宽度缩放 1.0~1.3 倍。
- 四种状态：待机卡、识别中、错误、结果卡。
- 结果卡包含首选、评分、理由、核心卡、开局路线、备选、8/5 流派。
- 用 Tk `Canvas` 显示 Pillow 图片并接收鼠标事件，整张卡片可拖动。
- 窗口置顶；扩展样式为 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_LAYERED`。
- 为了支持拖动，默认**不使用** `WS_EX_TRANSPARENT`；浮窗会接收鼠标，但 `WS_EX_NOACTIVATE` 保证不抢游戏焦点。
- 拖动结束把左上角写入 `data/overlay_position.json`；启动和每次显示时读取并按显示器工作区裁剪。

## 本地 HTTP / API

`ThreadingHTTPServer` 监听 `127.0.0.1`，默认 8777；占用时自动顺延。主要路由：

- `/`：网页控制台
- `/library`：英雄图鉴 / 卡牌库 / 规则
- `/api/status`：状态
- `/api/heroes`、`/api/hero`：英雄数据
- `/api/cards`、`/api/rules`：卡牌和规则
- `/api/recommend`、`/api/sample`：推荐
- `/api/guides`、`/api/guide`：攻略
- `/api/art-check`：立绘/图标自检
- `/static/*`、`/data/templates/*`、`/data/art/*`：静态资源

服务只监听本机，不对外网开放。

## 性能

在 2560×1600 示例画面实测：

- 截图约 0.07~0.12 秒；
- 识别 + 攻略检索 + 推荐约 0.9 秒；
- 首次加载 60 篇攻略和模板会比后续稍慢。

AI 点评只在网页按钮触发，不在浮窗识别链路里。

## 已知限制

- 识别假设当前版本布局（5 个拱门、右下 4 列流派面板）。
- 游戏大版本改 UI 后需要更新 `data/templates/schools/*` 和网格参数。
- 独占全屏：浮窗无法覆盖、截图可能黑屏；请用无边框窗口。
- 受保护画面或反作弊渲染可能阻止 GDI 截屏。
- 截图至少 640×360，且包含完整面板。
- 浮窗只读，不支持在浮窗上修正英雄/流派。
- 自动识别模板目前只有 3 个；其余 57 个英雄靠手动选择/学习。
