# 真实帧 holdout 流程

`tools/run_accuracy.py` 能算准确率，但只有两套固定验证图时，数字只能证明“这两张没坏”。本流程把真实截图持续纳入回归，目标是 10 组起步、逐步扩到 50–100 组。

当前仓库有 **10 组**独立真实帧：1800×1118 无边框、2153×1179 窗口化，4 张 1920×1080 / 2560×1600 的 30/80 亮度截图，以及 4 张 2560×1390 四英雄截图（A/B/C/D）。图片统一放在 `tests/fixtures/screenshots/`，holdout 只保留 `client` / `expected_file` 引用。CI 的 holdout 门槛为 `--min-cases 8`（10 组留 2 组余量）。不要为了凑数提交同屏连拍或合成图。

4 张旧全屏素材只人工核对了英雄名，流派没有逐图标复核，因此流派统一记为 `null`；其中 `screenshot_2560_80` 的流派分段本身也失败（`run_count 13`）。新 A 组有已核对的 8 启用 / 5 禁用流派；B/C/D 只登记英雄名，流派为 `null`。它们只作为英雄识别回归，不是流派回归通过的证据。C 组（`极寒掌控者 / 狂暴战将 / 星涡语者 / 赏金猎人`）作为真实失败样本入库；全名兜底修复后通过，但不得用 C 自身训练模板，也不得用合成标签“凑绿”。

## 1. 采一帧

- 游戏用**无边框窗口**，确认浮窗已隐藏、没有遮挡名牌。
- 优先截取完整客户区，保存为 PNG；不要裁掉边缘，也不要把桌面截进来。已有全屏素材可以保留标题栏作为压力样本，但必须在 `--note` 里写明“全屏，含标题栏”。
- 选稳定帧：名牌文字完整、底部流派图标没有动画残影。

## 2. 登记标签

```powershell
python -X utf8 tools/import_validation.py `
  --image "D:\captures\holdout_001.png" `
  --name holdout_001 `
  --heroes "森林游侠,神秘法师,魔镜" `
  --schools "普攻流,大招流" `
  --note "2560x1600 无边框"
```

- `--heroes` 按屏幕从左到右的顺序填写，可以写别名；脚本用 `Advisor` 的闭集转成正式名。
- 未知英雄、重复英雄、未知流派会拒绝导入，避免把错标签写进基线。
- 不确定流派时省略 `--schools`，记为 `null`。
- 同名案例用 `--replace` 显式覆盖。
- 导入器会拒绝**同一帧的重复内容**（按解码后的 RGB 像素计算 SHA-256），也会拒绝**分辨率 + 英雄 + 流派标签完全相同**的案例，避免把同屏连拍当独立样本。
- 每张图会记录 `sha256`、`resolution` 和仓库内 `source`，便于复核来源。
- 图片和 `meta.json` 都先写临时文件再替换，导入失败不会留下半套案例。

默认目录是 `samples/validation/holdout`，也可以 `--dataset` 指到别处。

## 3. 跑准确率

```powershell
python tools/run_accuracy.py `
  --meta samples/validation/holdout/meta.json `
  --min-cases 8 `
  --strict `
  --out holdout_accuracy.json
```

输出包含：

- `slot_accuracy`：按屏幕槽位对齐，未识别记为错；
- `name_accuracy`：只统计非空期望英雄；
- `exact_case_rate`：整张图英雄序列完全一致；
- `p50_ms` / `p95_ms`：离线识别耗时；不是游戏内端到端延迟；
- `failures`：逐案例期望/实际，便于定位。

`--min-cases` 是防回退门槛：实际案例少于门槛时 `--strict` 必须失败。CI 已经跑这条命令，当前门槛为 8；每补一批独立真实帧就往上提一档，达到 10 组后维持 8（余量 2），再按阶梯向 25/20 提高。

## 4. 扩到 10 组（再扩到 50–100）

优先补齐这些桶，避免只测一种窗口：

| 维度 | 目标 |
| --- | --- |
| 分辨率 | 1080p 2 组、2K 2 组、4K/超宽 2 组，加上现有 1800px/2153px |
| 窗口模式 | 无边框、窗口化都要有 |
| 英雄数 | 至少 1 组 5 英雄，至少 1 组 1–2 英雄 |
| 名牌 | 至少 1 组含“特权解锁/随机” |
| 流派 | 至少覆盖 8 启用 / 5 禁用各一轮 |
| 亮度 | 亮背景、暗背景各一半 |

新增图片和 `meta.json` 一起提交；不要提交含账号名、聊天窗口或其他个人信息的截图。

## 5. 与固定样例的关系

- `samples/validation/meta.json`：两套固定样例，CI 每次都跑，防止基础能力回退。
- `samples/validation/holdout/meta.json`：真实分布，当前 10 组，已接入 CI；样本增加后提高 `--min-cases`。
- `tests/fixtures/`：M1 静态回放的唯一真实图用例源。当前 10 组（2 张草稿 + 4 张旧全屏 + A/B/C/D），
  holdout 只保留 `client` / `expected_file` 引用，不再维护第二套标签。pytest 自动发现 fixtures
  并打印 `N / 目标 10，缺口 N`；当前为 `10 / 目标 10，缺口 0`。

三条路径都用同一套识别管线；改识别参数时至少跑 pytest + 固定验证集，涉及真实分布时再跑 holdout。
模板分组（hd/fhd/qhd）目前共享同一套 1800px 参考模板，选择逻辑已接入运行时，但尚未按分辨率
重新采样；在补齐分组模板前，不要对外宣称已针对 4K 校准。
