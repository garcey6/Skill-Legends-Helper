# 攻略库、检索与评分

本文解释推荐结果从哪里来，以及如何维护攻略数据。只想知道怎么用，见 [USER_GUIDE](USER_GUIDE.md)。

## 攻略库现状

- `data/guides/` 内置 **60 篇**英雄构筑攻略，60 个英雄逐位覆盖。
- 每篇包含主副流派、抓牌顺序、克制关系、常见失误和候选卡池依据。
- 网页「攻略库」可以直接编辑；保存后立即重建索引，下一次识别生效，不用重启。
- `data/hero_builds.json`、`data/curated_plans.json` 是知识库的生成/审计数据，供维护和全英雄速查使用，**不直接参与界面评分**。评分仍由 `app/kb/recommend.py` 的结构化模型产生。

## 添加或修改攻略

**网页内编辑**

1. 双击 `打开设置.bat`。
2. 右上角「攻略库」。
3. 选择英雄，编辑 Markdown，保存并重建索引。
4. 下一次识别自动加载。

**直接放 Markdown**

文件路径：`data/guides/<英雄名>.md`。

```markdown
---
hero: 神秘法师
title: 神秘法师 · 大招精灵双修
tier: S
schools: 大招流, 精灵流, 急速流
patch: "2026.10"
source: 我的实战笔记
updated: 2026-10-26
---

# 神秘法师 · 大招精灵双修

## 一句话结论
...

## 适配流派
...

## 开局抓牌顺序
...
```

规则：

- `hero` 必填，必须与 `data/heroes.json` 的 `name` 完全一致。
- `##` 二级标题会切成检索块。
- 推荐固定写「一句话结论 / 核心机制 / 适配流派 / 开局抓牌顺序 / 宝物与技能选择 / 克制关系 / 常见失误」。
- 网页保存后 `Advisor.reload()` 立即重建索引。

## 检索流程

```text
候选英雄 + 8 启用 + 5 禁用
        │
        ▼
查询串：英雄名 + 流派名 + "开局 抓牌 宝物 克制 强度"
        │
        ▼
按英雄过滤 → BM25 段落排序 → Top 3 证据
        │
        ▼
结构化评分 + 攻略证据
        │
        ▼
浮窗展示理由/路线；网页展示完整证据
```

BM25 使用中文 bigram 分词（「大招流」→ 大招 / 招流），不依赖 jieba；参数为 `k1=1.5, b=0.75`。

## 推荐评分

```text
总分 = 0.42 × 基础强度
     + 0.30 × 流派契合
     + 0.18 × 本局环境
     + 0.10 × 版本数据
     + 灵活性加成（最多 4 分）
```

| 维度 | 计算方式 |
| --- | --- |
| 基础强度 | `data/heroes.json` 的 `power`（0-100） |
| 流派契合 | `30 + 28 × Σ(英雄与启用流派的契合度)`，上限 100 |
| 本局环境 | 55 起；主系开放 +8/个，主系被禁 -14/个；怕的流派被禁 +7、开放 -7；完全无契合 -12 |
| 版本数据 | 默认 50；`data/meta_stats.json` 有胜率时按 `50 + (胜率-0.5)×300` |
| 灵活性 | 启用流派中契合度 ≥0.5 的副系数 ×1.3，上限 4 |

置信度：

- 高：有攻略、领先第二名 ≥4 分、总分 ≥70。
- 中：领先 ≥2 分。
- 低：没有攻略，或差距 <2 分。
- 非首选卡统一标记「备选」。

`data/heroes.json` 的 `power`、`schools`、`weak_to` 可直接改，下一次请求立即生效。

> 当前数值是初始示例数据：来自公开攻略的定性结论和通用对局经验，不是官方胜率。它的作用是让流程先跑通并给出可解释排序；逐条校正后会越来越准。

## 核心卡选择

`app/kb/cards.py` 按以下信号排序：

1. 只从本局**已启用**的流派里选，被禁流派的卡不推荐。
2. 优先传说卡，再考虑稀有和普通。
3. 双流派卡优先，因为它能同时推进两条线。
4. 主系重合度越高越靠前。
5. 同一主系最多两张，避免 6 张全是同质攻击卡。

浮窗显示前 3 张和首卡效果；网页英雄详情显示 6 张完整效果。

## 可选 AI 点评

网页控制台 → 右上角「设置」：

- API 地址：`https://api.deepseek.com/v1` 或任意 OpenAI 兼容地址。
- 模型：`deepseek-chat`。
- API Key：只保存在本机 `data/settings.json`。

不配置也能用。配置后，在网页结果卡点「AI 点评」，模型只会收到本局结构化数据和攻略摘录；系统提示词要求它不能编造机制或数值。浮窗本身不调用模型，保证识别速度。

## 数据边界

- 英雄 `power/tier` 是整理/面板估算值，不是官方胜率。
- 卡牌表只提供 `base_val_1`；`{valN}` 按基础值 × N 渲染，实际以游戏内卡牌等级为准。
- 构筑攻略尚未经过实战胜率验证；请结合本局开放流派、已有牌、宝物和对手调整。
