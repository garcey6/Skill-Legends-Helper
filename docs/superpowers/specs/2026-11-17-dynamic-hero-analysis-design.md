# 动态英雄数 + 全英雄分析 + 统一入口

日期：2026-11-17  
状态：待批准（批准后才进入实现计划）  
选择：分析界面采用 **A. 浮窗自动加高，所有英雄纵向列出；超高时滚动**

## 目标

1. 选人界面顶部石质名牌里有几个英雄，就识别几个；不再固定 3 个。
2. 浮窗把每个英雄的完整方案都列出来：评分、定位/路线、理由、核心卡、开局，而不是只完整展示第一名。
3. 只保留一个 `启动助手.bat` 入口，把浮窗、网页、设置统一成菜单。

## 非目标

- 不重做流派识别，不改 RapidOCR 模型，不改推荐打分权重。
- 不支持超过 5 个英雄（当前界面最多 5 个拱门）。
- 不把浮窗改成网页或独立窗口；本次就在现有浮窗内完成。

## 已确认的现状

- OCR 路径 `RapidOcrNameMatcher` 固定只返回 3 个候选，`detect_plates` 只取前 3 个石质名牌。
- 字模兜底 `GlyphMatcher` 固定补齐 3 个候选。
- 名牌 ROI 目前只到 `x=0.62`，第 4/5 个名牌不在抓取范围。
- 浮窗 `render_result` 只完整渲染 `cards[0]`；其他英雄只有名字和分数。
- 现有入口有 4 个 bat：`启动助手.bat`、`启动浮窗.bat`、`启动网页版.bat`、`打开设置.bat`。

## 方案选择

分析界面考虑过三种：

- A. 浮窗自动加高，所有英雄纵向列出；超过屏幕高度时滚动。**选中**
- B. 固定高度，按英雄标签切换；一次只显示一个。
- C. 独立分析窗口/网页；空间最大，但多一个窗口且可能抢焦点。

选 A 的原因：用户明确要求“每个英雄都列出来”，A 不需要额外窗口，也不要求用户点击切换。

## 设计

### 1. 动态英雄数

- 将 `data/recognize/layout.json` 的名牌 ROI 从 `x=0.02..0.62` 扩到 `x=0.02..0.98`，覆盖 5 个拱门。浮窗在抓帧前已经隐藏，扩大 ROI 不会截到助手自己。
- `RapidOcrNameMatcher.detect_plates` 返回最多 5 个石质名牌，不再 `[:3]`。
- 对每个名牌 OCR；识别到 `特权解锁`、`随机` 或它们的明显变体时，标记为“英雄结束”，不再加入候选。
- 英雄列表 = 第一个特殊名牌之前的所有名牌；保留槽位顺序。某个英雄 OCR 失败时保留 `null` 占位，不压缩数组。
- 如果 5 个名牌里没有特殊名牌，但前 5 个都命中 60 人英雄名，则按 5 个英雄处理；否则按实际检测到的英雄数处理，不强行凑 3。
- 字模兜底也改为动态候选：不再固定补齐 3 个；它只处理 OCR 失败的前 N 个英雄槽位。
- 推荐引擎 `Advisor.recommend` 已经支持任意数量的 hero_names，不需要改评分权重。

### 2. 浮窗全英雄布局

- 宽度保持 620；每个英雄一个完整区块，按推荐分数降序排列。
- 每个区块包含：
  - 头像、名字、评级、分数、置信度；
  - 定位与主/副路线；
  - 两条核心理由；
  - 3 张核心卡 chip + 第一张卡效果；
  - 开局第一句；
  - 天赋/大招图标（有数据时）。
- 顶部保留选中英雄的总标题？不单独突出第一名，只在第一名区块加“首选”标签，其余按“第 2 / 第 3 …”排列。
- 卡片高度自动计算：页头 + N 个英雄区块 + 8/5 流派区 + 页脚。
- 如果完整高度超过当前显示器工作区，浮窗进入**滚动模式**：
  - 窗口高度限制在工作区内；
  - 鼠标滚轮上下滚动内容；
  - 拖动仍移动整个浮窗；
  - 顶部/底部显示“滚动查看全部”的淡提示；
  - 保存的浮窗位置继续沿用。
- 3 个英雄时预计卡片约 900px，优先保证不用滚动；5 个英雄时允许滚动。

### 3. 统一入口

只保留一个 `启动助手.bat`，双击后显示菜单：

```text
1. 启动浮窗 + 网页（默认）
2. 只启动网页
3. 打开设置
4. 退出
```

- 复用现有的 Python 查找逻辑（DSH 运行时 → `py -3` → `python`）。
- 1 调用 `python agent.py --port 8777`；2 调用 `python run.py --port 8777`；3 读取 `data/server_url.txt`，没有则打开 `http://127.0.0.1:8777`。
- 删除 `启动浮窗.bat`、`启动网页版.bat`、`打开设置.bat`；README、INSTALL、USER_GUIDE、TROUBLESHOOTING 中所有入口说法同步更新。

## 涉及文件

- `app/vision/ocr.py`：动态名牌数、特殊名牌结束、动态候选。
- `app/vision/glyphs.py`：动态候选兜底，不再固定 3。
- `app/vision/pipeline.py`：动态候选透传、warnings 槽位数。
- `app/live/sampler.py` / `app/overlay/hud.py`：多英雄渲染、滚动视口。
- `data/recognize/layout.json`：名牌 ROI 扩到 5 个拱门。
- `启动助手.bat`：唯一入口菜单。
- 删除三个旧 bat；更新文档。
- 测试：`tests/test_ocr.py`、`tests/test_live.py`、新增 HUD 多英雄渲染测试、入口脚本检查。

## 验证

- 现有 43 项测试继续通过。
- 新增动态候选测试：模拟 3 英雄 + 特权 + 随机 → 3；模拟 4 英雄 → 4；某英雄 OCR 失败保留 `null`。
- HUD 渲染测试：1/3/5 个英雄图片高度递增；5 个英雄不抛异常；滚动视口能取到后半段。
- 回放 `samples/frames/draft_001` / `draft_002` 仍输出 3 英雄、8/5 流派。
- 人工检查：双击唯一 bat，菜单 1 能启动浮窗，菜单 3 能打开设置。

## 风险与约束

- 顶部第 4/5 个名牌可能被浮窗遮挡；自动层抓帧前会先隐藏浮窗，静态截图中的遮挡不作为验收。
- 如果 OCR 把“特权解锁”识别成近似英雄名，按特殊词表优先排除，避免把功能位当英雄。
- 5 个英雄时卡片较高，滚动是必要兜底；不采用缩小字体来硬塞。
- 本次不改网页手动上传的旧 `recognizer.py` 路径；自动浮窗是主路径。如果之后要求网页也动态，再单独改。
