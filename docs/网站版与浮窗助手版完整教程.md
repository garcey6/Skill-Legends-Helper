# 网站版与浮窗助手版完整教程

本教程对应指定仓库提交 `2922416928acb75c3059f9aae677d81ea63bfd6b`。这里的“网站版”是本机网页控制台；“浮窗助手版”是Windows上的截图识别与置顶提示窗口。本分支已内置60篇详细攻略，运行时仍需完整克隆仓库，保留代码、图片和识别模板。

## 一 获取并准备项目

1. 打开[项目仓库](https://github.com/garcey6/Skill-Legends-Helper)，选择 **Code → Download ZIP**，解压完整压缩包。也可用Git克隆。
2. 找到同时含 `run.py`、`agent.py`、`data`、`requirements.txt` 和启动批处理的目录。这才是项目根目录；当前仓库文件直接位于根目录，不要机械寻找名为“选技助手”的额外子目录。
3. 浮窗版使用Windows。安装带Tkinter的Python 3.10或以上；项目启动器还会尝试使用已有的DSH运行时。
4. 在项目根目录打开PowerShell，安装并检查依赖。以下路径替换成自己的项目路径。

```powershell
# 步骤1：进入完整应用的根目录。
Set-Location 'D:\Games\Skill-Legends-Helper'
# 步骤2：为同一个Python安装应用需要的两个第三方依赖。
python -m pip install -r requirements.txt
# 步骤3：检查图像处理、数组和浮窗依赖是否可导入。
python -c "import numpy, PIL, tkinter; print('依赖检查通过')"
```

应用运行只需numpy、Pillow与标准库Tkinter。openpyxl只在重新导入Excel或复核原表时需要，不是日常启动的必需依赖。使用多个Python时，安装依赖和启动应用应使用同一个解释器。

## 二 使用与更新知识库

本分支已将60篇攻略放入 `data/guides`，启动后即可在图鉴和攻略库中阅读，无需再安装补充包。

如果要维护攻略，修改 `data/curated_plans.json` 中的英雄方案、`data/sources.json` 中的证据来源，或生成器中的逐牌说明，然后在项目根目录运行：

```powershell
# 步骤1：进入完整应用的根目录，按实际路径修改。
Set-Location 'D:\Games\Skill-Legends-Helper'
# 步骤2：根据当前仓库数据生成攻略；此命令会覆盖生成文档，请先保存手工修改。
python -X utf8 tools/build_guides.py
# 步骤3：重启助手，让网页和浮窗重新加载知识库。
```

生成器只需要Python标准库。原始英雄与卡牌数据不被改写；用Git差异检查生成文档后再提交。完整维护与核验方法见[攻略知识库维护README](攻略知识库维护README.md)。

文档采用原项目需要的 `hero`、`title`、`schools`、`patch`、`source`、`updated` 字段；`hero` 必须与 `data/heroes.json` 完全相同。网页内点击保存会立即重建索引。

## 三 网站版从启动到推荐

1. 双击项目根目录的 **启动网页版.bat**。保留控制台窗口，它是正在运行的本地服务。
2. 浏览器通常会自动打开。默认地址为 [http://127.0.0.1:8777](http://127.0.0.1:8777)；端口被占用时会依次尝试之后的端口，以控制台实际地址为准。不要直接双击 `static/index.html`。
3. 先点 **试试示例**，检查页面能否返回候选英雄和启用、禁用流派。这只能验证示例流程，不代表已识别你的游戏。
4. 实际使用时，在游戏开局选人界面截取完整画面，拖入上传区域、选择图片，或粘贴剪贴板图片。保留完整的候选英雄区与流派面板，图片至少640×360。
5. 逐一检查识别的 **3位候选英雄、8个启用流派、5个禁用流派**。只有三个头像模板随仓库提供，其余英雄第一次出现可能需要修正。
6. 英雄不正确时，在对应下拉框选择正确英雄。程序在有有效头像裁切时会尝试保存头像模板，成功后出现已记住头像的提示。
7. 流派不正确时，点击对应流派标签在启用和禁用之间切换；操作完仍应为8启用、5禁用。不要为了看某个构筑而把实际被禁流派改成启用。
8. 点击 **生成推荐**。读首选、备选、理由和证据片段，再结合完整攻略判断。评分不是胜率，差几分也不是胜负保证。

命令行方式：

```powershell
# 步骤1：在完整应用目录启动网站，不自动打开浏览器。
python run.py --port 8777 --no-browser
# 步骤2：浏览器访问控制台打印的实际URL。
```

结束时在该控制台按Ctrl+C，或关闭该控制台。只关浏览器标签页不会停止服务。

## 四 网站版查询卡牌和阅读攻略

1. 点右上角 **图鉴**，或在实际端口后访问 `/library`。
2. 在英雄图鉴选择英雄，查看天赋、大招和属性；展开底部的 **查看攻略**。
3. 本次攻略每位都有主副流派依据、分阶段抓牌、两个完整18种候选池、共享卡去重、反制、常见误区和来源。
4. 当前界面用纯文本块显示完整Markdown，所以表格可能显示竖线，链接也可能不能直接点击。需要更清晰阅读时，在项目目录中打开对应Markdown文件。
5. 卡牌库按名称、效果、流派或稀有度筛选。双流派牌能在两个流派筛选中出现，但仍是同一个ID。
6. 规则页适合速查；涉及占位符倍率、特殊英雄例外时，同时看本次规则核对文档。

图鉴上方的6张“核心卡”由原程序自动排序，浮窗只展示其中较少几张；它们不是本次完整攻略里人工核对的全部优先级。尤其魔镜攻速、蛛王固定毒暴击、循环目标竞争等，应以攻略中的机制说明为判断依据。

## 五 网站版编辑知识库

1. 在网页控制台点右上角 **攻略库**。
2. 左侧选英雄，编辑右侧正文。已有本次攻略时，不要点“插入模板”覆盖它。
3. 若为新建条目，可点 **插入模板**，保留准确的 `hero` 字段。
4. 使用 `##` 标题划分“一句话结论、核心机制、适配流派、开局抓牌顺序、克制关系”等段落，便于检索。
5. 点 **保存并重建索引**，看到保存成功提示后再关页面。
6. 再次打开该英雄攻略，确认内容已经保存；下一次推荐会加载新内容。

网页编辑保存只改本机文件，不会自动提交到GitHub。AI点评是另一个可选入口，普通识别和本地知识库检索不需要API Key。

## 六 浮窗助手从启动到使用

1. 在游戏设置中切换为 **窗口化** 或 **无边框窗口**。独占全屏可能让浮窗无法覆盖，并导致截图黑屏。
2. 双击 **启动助手.bat**，它调用 **启动浮窗.bat**。看到待机浮窗后，先记录控制台和浮窗显示的实际快捷键。
3. 回到游戏，进入完整开局选人界面。**不需要按键**：浮窗会在画面稳定后自动识别；想立即重算按 `Alt+C`（冲突时可能换成 F6）。
4. 程序只抓底部图标条和顶部前 3 个名牌两个 ROI，识别后显示推荐；不再依赖右下角 13 流派面板。
5. 核对英雄与流派。遇到未识别英雄时，先按隐藏键，再用网页控制台修正。
6. 按住浮窗卡片拖动到合适位置，松开后位置会保存。`Alt+X` 显示或隐藏（冲突时可能换成 F7）。
7. 退出默认是 Ctrl+Alt+Q，冲突时可能用 Ctrl+Shift+Q；以实际显示为准，也可以关闭助手控制台。

|默认键|作用|常见替代|
|---|---|---|
|Alt+C|强制重识别（正常自动，不需要按）|F6|
|Alt+X|隐藏或显示浮窗|F7|
|Ctrl+Alt+Q|退出助手|Ctrl+Shift+Q|

自定义启动：

```powershell
# 步骤1：进入完整应用目录后，指定不会与游戏冲突的按键。
python agent.py --capture-key Alt+C --toggle-key Alt+X --quit-key Ctrl+Alt+Q
# 步骤2：若不需要网页控制台，可改用下面这一条单独启动。
# python agent.py --no-server
```

`--hud-scale` 控制缩放，`--alpha` 控制不透明度，`--no-save-capture` 可关闭最近截图保存。只在确有需要时调整，默认设置便于首次排查。

## 七 浮窗识别错了怎么修正

1. 按实际隐藏键收起浮窗，双击 **打开设置.bat**，或访问控制台的实际网页地址。
2. 上传同一张选人截图；默认最近截图位于应用 `data/captures/last.png`。
3. 在网页下拉框选择正确英雄，确认已记住头像；流派错误则手工修正启用和禁用标签。
4. 回到游戏前台，浮窗会自动重新识别；也可以按 `Alt+C` 强制一次。

现有浮窗不支持直接下拉修改英雄或流派，也不会把手工修正后的任意流派永久当作未来对局结果。自动识别英雄名用本地 RapidOCR + 60 人闭集校正，OCR 失败再回退 155 字字模；和 60 张展示立绘是两套东西，立绘不参与识别。

## 八 不开游戏的验证方式

网站版直接点“试试示例”。浮窗版先启动助手，再在完整项目目录运行：

```powershell
# 步骤1：显示仓库提供的选人示例，最多30秒。
python tools/preview_draft.py 30
# 步骤2：示例在前台时按实际识别键；Esc可提前关闭示例。
```

预览会创建可见窗口，仅在你主动测试时运行。这个方法检验示例识别与浮窗显示，不验证真实游戏中的所有英雄、分辨率或版本UI。

## 九 常见故障

|现象|检查与处理|
|---|---|
|双击启动立即报缺依赖|用启动器实际采用的Python安装numpy和Pillow；浮窗还需要Tkinter。|
|浏览器打不开|保留服务控制台，复制实际URL；端口可能不是8777。|
|打开设置跳到旧页面|该批处理读取 `data/server_url.txt`；优先采用当前控制台地址，纯网站服务不保证更新这个文件。|
|F8无反应|看实际快捷键，点回游戏前台；必要时用参数改键。|
|提示焦点在浮窗或控制台|点击游戏后再识别，避免截到助手本身。|
|黑屏、浮窗盖不上游戏|改无边框或窗口模式；检查完整面板是否在屏幕内。|
|新英雄显示空白|在网页用同一截图修正并学习模板。默认只含森林游侠、神秘法师、魔镜三个识别模板。|
|图鉴没图片|必须通过本地服务访问；完整仓库应包含 `data/art`。检查 `/api/art-check`，再重启服务并Ctrl+F5。|
|新攻略没出现|检查 `data/guides` 路径和frontmatter里的准确英雄名；重启服务或网页保存重建索引。|
|浮窗位置不合适|直接拖动；确需重置时，关闭助手后先备份再移走 `data/overlay_position.json`。|
|评分看起来与攻略不同|评分、主副系权重和短卡片仍是原项目逻辑；本次更新的是详细知识库，不是实战训练过的新评分模型。|

## 十 更新与恢复

游戏或数据更新后，先核对英雄技能、卡牌数据和版本公告，再修改 `data/curated_plans.json` 并重新生成；不要把文档日期理解成永久适用。

恢复旧稿前先保存当前修改，再通过Git历史取回对应的攻略版本。如果使用生成器的 `--install-to` 参数更新另一个项目，旧稿另存于目标项目的 `data/guide_backups/时间戳/`，可从该目录恢复同名文件。
